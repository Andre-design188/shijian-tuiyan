# 质量标准

## Definition of Done

- 用户可见行为符合 `SKILL.md` 的流程、引用纪律和安全边界。
- 易经决策工作流覆盖全部九个原则；每步有篇章、原典链接、现代转译、自检问题和边界；模型按固定顺序分析，不选单一“镜头”，不作占卜或结果预测。
- 展示页主导航与内容顺序为「三源决策法 → 史鉴方法论（《史记》《资治通鉴》）→ 易经九步」；旧有六条易经思想精要、完整九步决策工作流与醒目的历史案例库入口均须保留。
- 展示页必须说明三者如何参与底层决策：两书按人物视角与编年局势视角各自提供历史证据，易经九步提供复核流程；实时结果列出本次实际匹配的史书案例与九步方法，缺失的史书证据须明确说明，不得伪装覆盖。
- 三个示范默认以主题入口卡片呈现；点击单个入口后只展示对应完整推演，示范内易经复核采用三组简明检查，并链接至完整九步专区。92 条历史案例默认只显示 6 张卡片，可搜索、筛选或按需加载；来源质量说明和勘误内容仍可访问。
- `scripts/build_site.py` 检查六条易经精要、原则字段、ID 唯一性、流程完整性、HTTPS 链接与所有示范的综合应用；结构检查不能代替逐版本校勘或独立学术复核。
- 案例库变更通过完整引文核验（先有语料）及说人话检查。
- 修改案例、示范或页面源后，`python scripts/build_site.py` 成功生成发布页面和示范文件。
- 本机服务相关改动保留回环绑定、同源校验、请求体限制；Codex CLI 使用只读沙箱且最终输出受 JSON Schema 约束。
- 生成文件与源内容一致；文档随架构、命令和约定变化同步更新。
- 变更范围、验证结果和未解决问题写入 `progress.md`；按 `tasks.json` 中验证步骤完成后更新任务状态。

## 代码审查检查清单

**正确性与内容**

- [ ] 案例有完整必填字段、有效来源卷、史料等级理由和存在的对照 ID。
- [ ] 模型引用来自已核验案例；C 级材料没有被写成依据。
- [ ] 新增建议说明相似点、决定性差异、前提和止损信号。

**安全与隐私**

- [ ] 用户输入和 API Key 不写日志或仓库。
- [ ] 本机 HTTP 服务只监听本机，校验请求来源并限制请求大小。
- [ ] Codex CLI 调用保留只读沙箱、非交互执行和 JSON Schema 输出约束。
- [ ] 自伤危机及专业问题仍符合 `SKILL.md` 的处置规则。

**生成与维护**

- [ ] 修改 `references/cases/`、`examples/demos.json` 或 `site/` 后运行 `build_site.py`。
- [ ] 没有手改 `docs/index.html`、`.nojekyll` 或生成的示范 Markdown 作为唯一变更。
- [ ] 共享的简繁/标点归一规则变动时，Python 与 JavaScript 实现保持一致。

## 测试与检查要求

- `python scripts/check_plain.py`：不需语料；GitHub Actions `plain.yml` 每次推送及 PR 执行。
- `python scripts/verify_quotes.py`：结构检查及引文逐字核验；完整检查前运行 `pip install -r requirements.txt` 和 `python scripts/fetch_corpus.py`。CI 的 `verify.yml` 会下载语料后运行。
- `python scripts/build_site.py`：校验案例、示范、勘误关系并生成页面。
- `python scripts/find_cases.py --list`：快速确认案例读取与母题索引。
- 当前未发现独立单元测试套件或浏览器自动化测试。不要把脚本型数据检查称为单元测试；新增行为测试前先补充维护约定。
