# 业务解决方案

## 一句话定位

面向正在权衡多个现实选项的人，用《史记》《资治通鉴》中结构相似的正反案例帮助识别决定变量、代价和退出信号。历史提供比较材料，不替用户作决定。

展示页明确分为三类并列内容：产品的决策推演示范、《史记》《资治通鉴》的来源说明与案例库、易经原有精要及现代九步决策方法。入口与导航使三类内容都能直接到达。

底层实时推演也将三者合并在同一流程：依据《史记》人物选择材料与《资治通鉴》时序局势材料检索、比较正反历史案例；再用《易经》现代九步流程检查事实、变化信号、行动时机、责任边界、风险与复盘。界面会逐项显示本次所用史料与原则；若匹配案例不含某部史书，会明示未用其作为直接证据。

## 目标用户与核心任务

| 用户/角色 | 核心任务 | 当前痛点 |
|---|---|---|
| 面临职业、合作或家庭重大选择的人 | 梳理选项、资源、关键关系、窗口期和最坏后果 | 容易只看眼前收益，忽略隐性成本、反例和退出条件 |
| 使用网页或 Agent Skill 的个人 | 通过追问和案例对照得到行动建议 | 泛泛的历史故事难以对应自己的局面，也可能混淆原文和演绎 |
| 维护者/贡献者 | 维护案例、来源、引文和推演体验 | 引文、史料等级和生成网页需要可重复核查 |

目标用户来自 README、`SKILL.md` 和页面入口说明；项目未说明商业模式、用户规模或运营指标，需业务负责人补充。

## 典型业务场景

1. **去留选择**：用户描述岗位、平台、资源和离开成本；技能检索去留等母题案例；结果比较留下、离开或先试探，并给出退出条件。
2. **合作或创业**：用户说明伙伴关系、分工和机会成本；系统取合伙、择主、孤注等案例；结果强调书面条款、资源依赖和反例。
3. **家庭接班或回乡**：用户补充家庭关系、企业现状及个人退路；系统对照交班、家教、名实案例；结果列出需要先谈清的权限与边界。
4. **推演结果核引**：模型返回结构化结果后，网页按案例库内已校验的引文逐字比对；无法命中的引文会隐藏并提示。

以上场景由 `SKILL.md`、案例母题、网页引擎和示范文件支持。具体用户效果没有独立评估。

## 核心业务流程

1. 用户输入当前处境和所求。
2. 系统询问最多三个会影响结论的问题，并映射到相关母题。
3. 从案例库取正反镜像，展示同构点、差异、史料等级和边界。
4. 对各选项推演近期、中期、远期结果，标明翻车路径和预警信号。
5. 给出带前提和止损线的建议及本周行动卡。
6. 网页校验模型输出的案例编号和古文引文；本机推演通过本地服务调用只读沙箱内的 Codex CLI。

## 能力边界

- 案例库是有限样本，不代表历史全貌，也不能推导现代事件成功概率。
- 易经工作流是基于经传材料的当代项目综合，不是古代固定程序，不能预测结果或证明某个选择正确；原典年代、作者和解释存在学术讨论，项目页面链接具体篇章文本并说明应用边界。
- 引文逐字核验依赖本地下载的维基文库语料；未下载语料时不能宣称完成全文核验。
- 史料 A/B/C 是项目维护者采用的使用等级，不等同于学术机构的正式鉴定。
- 用户输入发给用户选用的 AI 服务；使用在线模型或自带 API Key 时应自行脱敏。仓库未提供服务端存储实现。
- 本机服务只监听回环地址并有限制请求来源，但使用者仍需保护本机凭据和终端环境。
- 不用于危机干预、医疗、法律、税务或具体投资的专业判断；相关场景必须提示求助专业人士，轻生表达按 `SKILL.md` 停止推演并先关怀。
- 可用性、准确率、隐私合规等级、SLA 和决策效果没有量化承诺或独立评估。
